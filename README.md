# vk_claude_bot

Личный ассистент на Claude, доступный из переписки ВКонтакте. Пишешь боту с
телефона — сообщение уходит на сервер, там его обрабатывает Claude Code, ответ
возвращается в тот же диалог.

Что умеет:

- отвечать на вопросы, помня контекст разговора;
- искать в интернете и читать страницы;
- смотреть присланные фото и документы;
- показывать, чем занят, пока думает («печатает» + заметки вида «🔎 Ищу: …»).

Чего **не** умеет — намеренно: выполнять команды на сервере, писать и править
файлы. Набор инструментов задан явно в `bot/claude_runner.py`, а
`permission_mode="dontAsk"` молча отклоняет всё, чего в нём нет.

## Как это устроено

```
телефон → ВКонтакте → Bots Long Poll → бот (контейнер на VPS)
                                        ├── проверка: id отправителя в белом списке
                                        ├── вложения → workspace/media/<peer_id>/
                                        ├── claude-agent-sdk: query(resume=session_id)
                                        └── ответ → messages.send (кусками по 4000)
```

**Long Poll, а не Callback API**: бот сам ходит за событиями исходящими
запросами, поэтому серверу не нужен белый IP, домен и HTTPS-сертификат. По той же
причине бот одинаково работает и с VPS, и с домашнего компьютера.

**Каждый собеседник — сам по себе.** Сессия Claude, очередь сообщений и контекст
заводятся на каждый `peer_id` отдельно, разговоры не смешиваются. Белый список
только решает, кого вообще пускать.

**Контекст** живёт в сессиях Claude Code: SDK пишет транскрипт на диск, а
`workspace/state.json` хранит связку «peer_id → session_id», чтобы разговор
пережил перезапуск. Разговор, в котором неделю молчали, забывается сам
(`SESSION_TTL_HOURS`) — иначе контекст растёт бесконечно и стоит токенов.

## Изоляция от остального сервера

Бот работает в Docker-контейнере со своим Node, своим Python и своим Claude Code
внутри. На сервере не появляется ни глобального `npm install`, ни системного
Python-пакета, ни правок в системных конфигах — только образ и один контейнер.
Соседние проекты бота не видят, он их тоже.

Всё, что бот пишет, лежит в одном месте — папке `workspace` рядом с проектом
(там же домашняя папка Claude Code с транскриптами). `deploy.sh uninstall`
сносит её, не задев ничего чужого.

### Потолки ресурсов

Заданы в `docker-compose.yml` по замеру на живом сервере: в покое бот держит
~50 МБ, пик на запросе с веб-поиском — ~400 МБ.

| Ограничение | Значение | Зачем |
| --- | --- | --- |
| `mem_limit` | 640 МБ | При превышении ядро убивает процесс **внутри контейнера**, а не выбирает жертву на хосте. Контейнер поднимается сам. |
| `memswap_limit` | 1280 МБ | Даёт 640 МБ swap на всплески: лучше подтормозить, чем словить OOM. |
| `cpus` | 0.8 | Жёсткий потолок: пятая часть единственного ядра всегда остаётся системе. |
| `cpu_shares` | 512 | Вдвое ниже стандартного веса — при споре за процессор соседи получают его первыми. |
| `pids_limit` | 256 | Зациклившийся агент не исчерпает таблицу процессов. |
| `oom_score_adj` | 800 | Если памяти не хватит всему хосту, ядро выберет бота, а не соседний сервис. |

Проверено под нагрузкой: CPU упирается в 81% при потолке 80%, тяжёлый запрос
проходит с пиком 362 МБ из 640, перезапусков и OOM нет.

Если на сервере есть сервис, который не должен падать никогда, стоит защитить и
его со стороны systemd — Docker управляет только своим контейнером:

```bash
sudo systemctl edit имя-сервиса
# [Service]
# OOMScoreAdjust=-900
```

Единственное, что скрипт может изменить в системе, — установка самого Docker, и
только если его нет и ты подтвердишь это вручную.

## Шаг 1. Сообщество ВКонтакте

1. Создай сообщество (vk.com/groups → «Создать сообщество»). Бот — это группа.
2. **Управление → Сообщения** → включить «Сообщения сообщества».
3. Там же **Настройки для бота** → включить «Возможности ботов».
4. **Управление → Работа с API → Ключи доступа** → создать ключ с правом
   «Управление сообщениями сообщества». Это `VK_TOKEN`.
5. **Работа с API → Long Poll API** → «Включён», версия API `5.199`.
6. Вкладка **Типы событий** → включить «Входящее сообщение» (`message_new`).

## Шаг 2. Токен Claude

На машине **с браузером** (не на сервере):

```bash
claude setup-token
```

Полученный `sk-ant-oat01-…` идёт в `.env` как `CLAUDE_CODE_OAUTH_TOKEN`. Это
долгоживущий токен для SDK — в отличие от кредов интерактивной сессии, его можно
спокойно отдать серверу.

## Шаг 3. Настройка

```bash
cp .env.example .env
# заполнить: VK_TOKEN, VK_GROUP_ID, ALLOWED_USER_IDS, CLAUDE_CODE_OAUTH_TOKEN

cp deploy/deploy.env.example deploy/deploy.env
# заполнить: VPS_HOST (и VPS_USER/VPS_PORT, если не root:22)
```

Оба файла в `.gitignore` — в репозиторий не попадут.

Проверить, что всё сходится, до всякого деплоя:

```bash
python -m scripts.check_setup
```

Скрипт дёргает VK API, проверяет Long Poll, показывает имена из белого списка и
задаёт Claude один вопрос. Секреты не печатает — только формат и длину, так что
вывод можно кому-то показать.

## Шаг 4. Установка на VPS

```bash
./deploy/deploy.sh install
```

Одна команда: проверит ssh, поставит Docker (спросит подтверждение, если его
нет), зальёт код и `.env`, соберёт образ и запустит контейнер.

На Windows запускать **из Git Bash**.

Дальше:

| Команда                      | Что делает                                |
| ---------------------------- | ----------------------------------------- |
| `./deploy/deploy.sh update`  | залить свежий код и перезапустить          |
| `./deploy/deploy.sh logs`    | живой лог                                  |
| `./deploy/deploy.sh status`  | состояние контейнера                       |
| `./deploy/deploy.sh stop`    | остановить                                 |
| `./deploy/deploy.sh start`   | запустить (и снять выключение через /stop) |
| `./deploy/deploy.sh shell`   | шелл внутри контейнера                     |
| `./deploy/deploy.sh uninstall` | снести бота с сервера                    |

## Команды в чате

| Команда   | Что делает                                                        |
| --------- | ----------------------------------------------------------------- |
| `/help`   | Справка                                                            |
| `/stop`   | Прервать текущий ответ; если бот свободен — выключить его на сервере |
| `/cancel` | Только прервать ответ, никогда не выключает                         |
| `/new`    | Забыть контекст этого разговора                                    |
| `/limits` | Сколько потрачено лимитов подписки и когда обнулятся                |
| `/status` | Чем занят, длина очереди, возраст контекста                         |
| `/clear`  | Полная очистка: все разговоры и все скачанные файлы                 |

`/stop` читается по обстановке: пока бот пишет ответ, это «прекрати», и он просто
прерывает работу. Выключение имеет смысл только когда бот и так свободен — тогда
он спрашивает подтверждение: первый раз отвечает «точно?», выключается
только если повторить `/stop` в течение двух минут. Любая другая команда между
ними отменяет запрос.

После `/stop` бот **сам не поднимется**: в `workspace/.killed` остаётся метка, и
при следующем старте процесс сразу выходит. Это переживает и перезапуск
контейнера, и перезагрузку сервера. Включить обратно — `./deploy/deploy.sh start`
(он снимает метку).

Ровно поэтому в `docker-compose.yml` стоит `restart: on-failure`, а не
`unless-stopped`: падение бот переживает и поднимается сам, а осознанное
выключение остаётся выключением.

### Про лимиты подписки

Точного процента расхода в этом канале **нет**. Событие от API выглядит так:

```json
{"status": "allowed", "resetsAt": 1786398000, "rateLimitType": "five_hour",
 "overageStatus": "rejected", "isUsingOverage": false}
```

Поля с процентом здесь просто не существует — цифра, которую видно на claude.ai
или через `/usage` в интерактивном Claude Code, приходит другим запросом,
недоступным из SDK. Поэтому бот работает по тому, что реально есть:

- `/limits` показывает состояние и время до обнуления;
- сам предупреждает отдельным сообщением, когда статус меняется на
  `allowed_warning` (подходим к лимиту) и на `rejected` (исчерпан) — по одному
  разу, отметки снимаются при обнулении окна.

Пороги 25/50/75 в коде остались и включатся сами, если API однажды начнёт
присылать `utilization`. Пока он приходит пустым.

## Настройки

Всё в `.env`, см. `.env.example`:

- `ALLOWED_USER_IDS` — белый список через запятую. Сообщения от остальных молча
  игнорируются; без этого любой, кто найдёт сообщество, будет тратить твою
  подписку Claude.
- `SESSION_TTL_HOURS` (168) — через сколько часов молчания забывать контекст.
  `0` — не забывать никогда.
- `MEDIA_TTL_DAYS` (7) — сколько хранить скачанные вложения. Уборка идёт раз в
  час и при старте.
- `SHOW_TOOL_PROGRESS` (true) — заметки о вызовах инструментов. Выключи, если
  мешают; индикатор «печатает» останется.
- `MAX_TURNS` (30) — потолок шагов агента на один вопрос, страховка от
  зацикливания.

Не выведено в `.env`, но задано в `bot/main.py`: очередь на собеседника — 5
вопросов (лишние отбиваются с объяснением), потолок на один ход — 15 минут
(зависший агент прерывается, а не держит очередь молча).
- `CLAUDE_MODEL` — явная модель, если не устраивает та, что Claude Code берёт по
  умолчанию.

## Локальный запуск

Бот прекрасно работает и с обычного компьютера — VPS нужен только чтобы он был
доступен круглосуточно.

```bash
python -m venv .venv
.venv/bin/pip install -r requirements.txt   # Windows: .venv\Scripts\pip.exe
python -m bot.main
```

Только не держи его запущенным одновременно локально и на сервере: два Long Poll
на одну группу начнут растаскивать события друг у друга.

## Структура

```
bot/
  config.py         чтение .env
  http.py           общий HTTP-клиент с корневыми сертификатами certifi
  vk.py             клиент VK API и цикл Long Poll
  media.py          скачивание вложений и уборка
  formatting.py     markdown → плоский текст, нарезка по 4000 символов
  sessions.py       peer_id → session_id, возраст и очистка разговоров
  claude_runner.py  Claude Agent SDK: промпт, инструменты, лимиты
  main.py           диспетчер, очередь на собеседника, команды
scripts/
  check_setup.py    проверка конфигурации перед запуском
deploy/
  deploy.sh         установка и управление на VPS
Dockerfile, docker-compose.yml
```

## Безопасность

- `.env` и `deploy/deploy.env` в `.gitignore`.
- На сервере `.env` кладётся с правами 600.
- Внутри контейнера бот работает не от root (uid 10001).
- У агента нет `Bash`, `Write`, `Edit` — ни в наборе инструментов, ни в
  разрешениях. Максимум, что он делает с файлами, — читает присланные тобой
  вложения.
- `Read` проходит через проверку в коде (`can_use_tool`) и разрешён только
  внутри рабочей папки. Иначе достаточно было бы попросить «прочитай
  /proc/1/environ» — или подсунуть такую инструкцию внутри веб-страницы, — и
  токены ВК и Claude оказались бы в переписке.
- Бот отвечает только в личных сообщениях: в беседах он молчит, иначе отвечал бы
  на каждую реплику любого, кто попал в белый список.
- Повторы событий Long Poll отбрасываются по id сообщения — иначе при
  переподключении один вопрос мог обработаться дважды и списаться дважды.
- `setting_sources=[]`: бот не подхватывает пользовательские настройки Claude
  Code и `CLAUDE.md`, поведение зависит только от кода в этом репозитории.
- Один вопрос за раз на собеседника, очередь ограничена пятью — параллельные
  запросы не разгоняют расход подписки. `/limits` во время работы не запускает
  второй процесс Claude: на сервере с гигабайтом памяти это верный OOM.
- `/clear` чистит **все** разговоры, а не только твой: если в этот момент с
  ботом переписывается кто-то ещё из белого списка, его контекст тоже обнулится.
